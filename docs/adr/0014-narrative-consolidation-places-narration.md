# One narrative layer: `places_narration` over a mute gazetteer

Narrative prose about quiet things is scattered across ~7 stores, each with its own fallback logic in code: `locations.description` (418 rows), `water.description` (32), `biomes.description` (a column nobody fills — 0 of 1190), `regions.description_*`/`land`/`people`/`products`, `region_biome_descriptions` (29k generated rows), `region_seasonal_descriptions`, `places_interactions`, and the ficha records in `places`. The readers — `placeNotes`, `waterNotes`, `terrainPhrases`, `seasonalVariants`, `placesInteractions` — implement five separate specificity ladders to answer one question: *what does the world say about this spot?*

We consolidate all quiet narrative into **`places_narration`** (the ficha table, renamed and extended): every record the world tells about a place, feature or scope — authored fichas (`place`/`ambient`/`arrival`/`lore`), depictions (`depiction` — a feature's, region's, kingdom's or generic scope's description) and interactions (`interaction` + `action`: `rest` folds `places_interactions`, `offer` the authored offers). Records carry no geometry: a record's position is always borrowed — `location_id` for hosted fichas (1:N, unchanged), `feature.depiction_id` for the thing it describes, or scope columns (`type`, `region_id`, `cultural_family`, `priority`) for generic records. Geometry tables keep `id + name + geom + depiction_id` plus mechanics columns only (encounter metrics, `cultural_family`, `water_type`, etc.): **mechanics stay, prose migrates**. Beings are out of scope — `entities` and `movers` remain their own family.

The binding is an **inverted FK**: each geometry row holds `depiction_id → places_narration.id`. One feature gets at most one depiction (1:1 enforced); many features may share one record (every `roads` segment of the East Road points to the same ficha). The authored truth stays in the `refs` column (`{"water":[12],"roads":[77,78]}`) — the seed materializes `depiction_id` from it on every run, so re-importing the gazetteer re-attaches links instead of orphaning them; `validate-seeds` reports depictions nothing points at and refs claiming the same feature.

The record shape is **columns first, payload last**: fields shared across kinds are real columns — `description` ({en,es}), `variants` (always an array of `{key|id, phrases|text, condition?}`), `mechanics`, `refs`, `action` — and `payload` keeps only kind-unique spec (ficha base/sections/beats/options/secret, region rotation/facts, provenance). Region and kingdom records are depictions (they already bind through `depiction_id`); overnights and offers are interactions (prose + mechanics/trigger), disambiguated by `action` — kinds describe *what the record does in the world*, not which legacy table it came from.

Amends ADR-0013 on three points: a narrative record no longer owns a `geom` (the gazetteer anchor's geometry is the only position truth — the old `places.geom`/`locations.geom` dual-write is dropped); `refs` stops being audit-only and now drives the materialized `depiction_id`; `locations.description` migrates to `depiction` records — the map UI and the narrator both read through the single resolver.

## Considered Options

- **Per-table descriptions, kept**: rejected — that is the status quo, with five parallel ladders and columns that are already empty in practice.
- **Typed FK columns on the narrative side** (`water_id`, `biome_id`, `road_id`…): rejected — it cannot enforce one-depiction-per-feature, multiplies nullable columns per new geometry table, and protects the wrong delete direction.
- **`feature_key` text (`'wat:55'`) as the runtime link**: rejected as a column — no cross-table referential integrity is possible; kept as the *authoring* format inside `refs`.
- **Keep `places_interactions` separate**: rejected — it already is the specificity ladder this design generalizes; folding it in is what makes one resolver possible.
- **Record-owned `geom`**: rejected — position would again live in two places (record and anchor), exactly the drift this decision removes.
- **Two-level type columns** (`type` + `type_class`): rejected — the coarse grouping (`village|town|city → settlement`) is a static map in the resolver code, never desynced from the native type columns.

## Consequences

- `kind` settles on six values: `place`, `ambient`, `arrival`, `lore`, `depiction`, `interaction` — an earlier draft spelled them as `region`, `kingdom`, `overnight`, `offer` (normalized in #106).
- `season`/`dayphase` are **variant keys in the `variants` column**, not scope dimensions — a lake in autumn is the same subject with different text; `region_seasonal_descriptions` and the region summary rotation fold into the same machinery.
- `region_biome_descriptions` stops being a queried table: its generator becomes an authoring tool that emits ~1–2k scope-bound depiction records (`type` × `region_id`) instead of 29k rows.
- Radii (`size_radius_km`, `influence_radius_km`) stay on the narrative record — they are resolver mechanics (when to tell), not cartography; two records on one anchor may legitimately reach differently.
- The 416 untyped `locations` are mostly georef anchors (~409): they default to `point_of_interest`, name-obvious ones get real types, and anchors get `source='georef'` to stay distinguishable from the imported gazetteer.
- Migration was staged inside one branch: additive schema (table + `depiction_id` columns) → backfill → single resolver → readers re-pointed one by one → column/table drops last, only after a `pg_dump` — georef positions and anchor rows are DB-only state, not covered by git. The drops landed in #104: `places_interactions`, `region_biome_descriptions`, `region_seasonal_descriptions`, all gazetteer prose columns, `places_narration.geom`, and `trip_days.places_interaction_id` (rewired to `places_narration_id` → `'ovn:*'`). Generated records (`dep:*`, `ovn:*`) reseed from `data/json/narration.json`, the canonical prose source.
- `CONTEXT.md` gains the vocabulary: Depiction, `depiction_id`, described-as vs hosted-at, and the mechanics/prose boundary.
